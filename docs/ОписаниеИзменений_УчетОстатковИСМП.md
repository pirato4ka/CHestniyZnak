## 2. Задача 1. Схлопывание итогов расхода: FIFO в разрезе «Номенклатура + GTIN»

**Было:** расход формировался по штрихкоду, указанному в строке табличной части документа.
Если приход учитывался по одной записи штрихкода упаковки, а расход — по другой (например, по
коду из документа), возникало «виртуальное» списание: остаток по приходной записи не
уменьшался, а по расходной уходил в минус.

**Стало:**

* `СформироватьДвиженияРасхода()` для каждой маркируемой строки табличной части «Товары»
  определяет коды маркировки документа и признак применения ОСУ (см. задачу 3).
* Для строк с ОСУ количество строки списывается по фактическим остаткам регистра
  `БНС_ОстаткиИСМП` методом FIFO в разрезе **Номенклатура + GTIN**:
  * GTIN извлекается из кодов `(01)`/`(02)` (в том числе без скобок: `01…`/`02…`), а для
    обычного штрихкода EAN-8/EAN-13/GTIN-14 — из самого значения (`ИзвлечьGTIN()`);
  * остатки читаются запросом к `РегистрНакопления.БНС_ОстаткиИСМП.Остатки()` и
    упорядочиваются по правилу FIFO (`ВыражениеПорядкаFIFO()`: дата упаковки штрихкода, если
    реквизит есть в конфигурации, иначе — по ссылке штрихкода);
  * движение расхода формируется **по той записи штрихкода упаковки, по которой числится
    остаток** (`ЗаписатьДвижениеРасхода()`), а не по штрихкоду из документа;
  * допускается частичное списание с одной записи: приход `(02)GTIN(37)27`, продажа 10 ⇒
    остаток по этой же записи становится 17 (запись не «пересоздается», виртуального расхода нет);
  * если по одному GTIN есть несколько входящих штрихкодов, количество распределяется между
    ними в порядке FIFO;
  * остаток в таблице расчёта уменьшается после каждого движения, поэтому один и тот же
    остаток не списывается дважды при нескольких строках с одной номенклатурой.

Группировка «Номенклатура + GTIN» реализована без изменения структуры регистра: GTIN
вычисляется из значения штрихкода упаковки, поэтому добавление измерения GTIN в регистр не
требуется.

## 3. Задача 2. Повторное и повторно-изменённое проведение

**Было:** при повторном проведении документ «видел» собственный расход в виртуальной таблице
остатков, из-за чего движения двоились либо выдавалось ложное сообщение о нехватке остатков.

**Стало:**

1. Перед расчётом и проверкой остатков старые движения документа физически сбрасываются
   (`ПодготовитьДвиженияКПересчету()`):

   ```bsl
   Движения = Источник.Движения;
   Движения.БНС_ОстаткиИСМП.Записывать = Истина;
   Движения.БНС_ОстаткиИСМП.Очистить();
   Движения.БНС_ОстаткиИСМП.Записать();
   ```

2. Остатки читаются на `МоментВремени()` документа с границей `ВидГраницы.Исключая`:

   ```bsl
   Запрос.УстановитьПараметр("Граница", Новый Граница(МоментВремени, ВидГраницы.Исключая));
   ```

   Собственные движения документа, записанные на его момент времени, в расчёт не попадают.

3. Перед чтением остатков устанавливается управляемая блокировка данных
   (`ЗаблокироватьОстаткиИСМП()`) по регистру `РегистрНакопления.БНС_ОстаткиИСМП` в разрезе
   измерения `Номенклатура` — по номенклатуре маркируемых строк документа.

Контрольный сценарий: реализация ОСУ на 10 шт → изменение количества на 15 шт → «Провести» ⇒
остаток уменьшается ровно на 15 (без дублирования 10 + 15).

## 4. Задача 3. Признак «ОбъемноСортовойУчет»

Реквизит движения `ОбъемноСортовойУчет` определяется функцией
`ПризнакОСУДляДвижения(Номенклатура, ДатаДокумента, ШтрихкодУпаковки)` (для расхода —
`ПризнакОСУПоКоду(...)`):

1. поштучный код DataMatrix `(01)GTIN(21)серийный номер` ⇒ `Ложь`;
2. групповой код ОСУ `(02)GTIN(37)Количество` либо упаковка с типом
   «Монотоварная упаковка» (`Справочник.ШтрихкодыУпаковокТоваров`, реквизит `ТипУпаковки`) ⇒ `Истина`;
3. в остальных случаях — по настройкам товарной категории (вида продукции ГИСМТ) на дату документа:
   `ОбщегоНазначенияИС.ОписаниеНоменклатуры()` →
   `КонструкторИСОбщегоНазначенияКлиентСервер.ВидПродукцииКлючаПоПодсистеме(…, "ГИСМТ")` →
   `ВидПродукцииИспользуетОбъемноСортовойУчет()`.

Результат кэшируется в пределах одного проведения (`ЭтоОСУСКэшем()`), параметр `ДатаДокумента`
передаётся во все точки вызова — признак ОСУ датозависим (это важно для перехода молочной
продукции со сроком хранения более 40 дней на поэкземплярный учёт с 01.11.2026).

Признак ОСУ в расходе при этом совпадает с признаком, по которому списывается остаток: движение
формируется по записи остатка, а тип кода/упаковки берётся из самой записи.

## 5. Задача 4. Нехватка кодов: частичный подбор запрещён, проведение не блокируется

`ПодобратьКодыМаркировки(СсылкаНаОбъект, СтрогийПодбор = Истина)`:

* Если по строке «Товары» `Остаток < ТребуемоеКоличество`, коды по строке **не подбираются
  вовсе** (нельзя подобрать 54 из 1000): номер строки попадает в `НомераСтрокБезКодов`,
  ранее подобранные (частичные) коды по строке не возвращаются в результат подбора, вызывающие
  процедуры очищают табличную часть `ШтрихкодыУпаковок` и заново заполняют её подобранными
  кодами — «осиротевшие» строки не остаются.
* Индикаторы маркировки строк, по которым коды не подобраны, переводятся в нейтральное
  состояние (`СброситьСтатусыМаркировкиСтрокТаблицыТоваров()` — сбрасываются служебные
  реквизиты-индикаторы табличной части «Товары», если они есть в конфигурации).
* Проведение документа не блокируется: `СформироватьДвиженияРасхода()` не устанавливает
  `Отказ`. Для строки без кодов движения по `БНС_ОстаткиИСМП` не формируются; для
  поэкземплярного кода, по которому нет остатка, движение не формируется (без «виртуального»
  расхода и отрицательных остатков).
* Массовая обработка `БНС_ЗаполнениеМаркировкиДокументыОтгрузки`: документ записывается в
  режиме проведения и по строкам без кодов; признак `КодыЗаполнены` выставляется по факту
  наличия подобранных кодов.

## 6. Задача 5. Сообщения по стандарту 1С:ИТС

* Единая точка вывода — `СообщитьПоСтрокеТоваров()`:

  ```bsl
  ПолеОшибки = СтрШаблон("Объект.Товары[%1].Количество", НомерСтроки);
  ОбщегоНазначенияКлиентСервер.СообщитьПользователю(ТекстСообщения, , ПолеОшибки, , Ложь);
  ```

  Сообщение привязывается к ячейке «Количество» конкретной строки табличной части «Товары»;
  параметр `Отказ` не взводится — сообщение информационное и не блокирует проведение.

* На каждую строку с нехваткой выводится **одно** сообщение (шаблон ТЗ):

  > По товару "…" недостаточно кодов маркировки (требуется %2 шт., доступно %3 шт.).
  > Коды маркировки для строки очищены. Документ может быть проведен без указания марок.

* `ВывестиСообщенияПодбора()` выводит сообщения по строкам и дополнительно прочие сообщения
  (например, о номенклатуре, отсутствующей в регистре «Описание номенклатуры ИС») — без
  дублирования уже выведенных текстов. Массовая обработка добавляет к тексту представление
  документа.
* Итоговое оповещение о результате команды — одно (`ПоказатьОповещениеПользователя`), без
  повторов сообщений по строкам.

## 7. Ограничения и допущения

1. **Регистр настроек товарных категорий.** Точное имя периодического регистра настроек
   (дат по сферам «Оптовая продажа (ОСУ)» / «Оптовая продажа (поэкземплярно)») в этой
   конфигурации не подтверждено и в расширении отсутствует. Определение признака ОСУ выполнено
   через штатный интерфейс подсистемы ИС МП (`ОбщегоНазначенияИС`, `КонструкторИСОбщегоНазначенияКлиентСервер`)
   в блоке `Попытка`; периодические настройки по датам этим путём не читаются. Если в
   конфигурации доступен регистр настроек с датами — определение ОСУ следует дополнить чтением
   этого регистра на `ДатаДокумента` (точка расширения — `ЭтоОСУ()`), поведение остального кода
   при этом не меняется.
2. **Связь марок со строками.** В табличной части `ШтрихкодыУпаковок` документа нет реквизита,
   связывающего строку марок со строкой «Товаров», поэтому команда «(БНС) Заполнить коды
   маркировки по остаткам» является командой по документу целиком: табличная часть очищается и
   заполняется заново (это соответствует варианту «очистить подчинённую ТЧ марок … или всего
   документа при общей команде»).
3. **Источник количества.** Объём кода определяется по реквизиту «Количество» справочника
   `ШтрихкодыУпаковокТоваров`, затем по идентификатору применения `(37)`, затем по числовому
   «хвосту» кода длиной более 31 символа; иначе — 1 единица (`КоличествоКодаМаркировки()`,
   `РаспарситьКоличествоИзКода()`).
4. **Адаптивные имена реквизитов.** Значение штрихкода читается из первого найденного реквизита
   `ЗначениеШтрихкода` / `Штрихкод` / `КодШтрихкода`, тип упаковки — из `ТипУпаковки` /
   `ТипТоварнойУпаковки`; порядок FIFO использует `ДатаУпаковки`, если реквизит существует.
   При поставке рекомендуется зафиксировать фактическую структуру справочника.
5. **Проверка платформой.** Модули написаны без возможности компиляции в среде разработки
   (1С в среде сборки отсутствует). Перед эксплуатацией требуется синтаксический контроль в
   конфигураторе 1С и прогон сценариев раздела 8.
